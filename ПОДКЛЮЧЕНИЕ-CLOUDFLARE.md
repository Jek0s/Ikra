# Запуск IKRA DeLuxe на Cloudflare D1

Домен сейчас покупать не нужно. Сайт и админка работают на бесплатном тестовом адресе `ikra-deluxe.ВАШ-ПОДДОМЕН.workers.dev`. Свой домен подключается позже. Платный хостинг Hostinger не нужен: Cloudflare размещает и сайт, и обработчик заказов.

База D1 хранит товары, акционные наборы, тексты разделов и заказы. Worker проверяет вход администратора, сохраняет изменения и отправляет заказы в Telegram. Фотографии из проекта уже доступны; для загрузки новых через админку подключается Cloudinary Free.

## 1. Создать аккаунт и войти

Зарегистрируйтесь на [Cloudflare](https://dash.cloudflare.com/sign-up). Для D1 и Workers выбираем Free. Домен добавлять на этом этапе не обязательно.

В терминале IntelliJ, в папке проекта:

```bash
npm install
npx wrangler login
```

Откроется браузер: войдите в свой аккаунт и разрешите Wrangler управлять Worker и D1. Пароли и API-токены в чат присылать не нужно.

## 2. Создать базу и таблицы

```bash
npx wrangler d1 create ikra-deluxe
```

Команда покажет `database_id`. Вставьте его в `wrangler.jsonc` вместо `00000000-0000-0000-0000-000000000000`. Остальные настройки можно оставить.

Примените таблицы и первоначальный каталог:

```bash
npm run db:remote
```

Добавятся текущие 7 товаров и 7 наборов. Миграции выполняются один раз: последующие запуски не перезаписывают изменения из админки. Тексты разделов сначала берутся из текущего макета; при сохранении раздела записываются в D1.

Правки, сделанные в демо-админке через localStorage, автоматически в D1 не переносятся. Если такие правки нужны, сначала сохраните их отдельно. Этот запуск использует каталог и тексты из файлов проекта.

## 3. Разместить сайт и настроить вход владельца

```bash
npm run deploy
npm run admin:remote
```

Первая команда соберёт и разместит сайт, затем покажет его HTTPS-адрес. Пока вход владельца не настроен, админка закрыта для редактирования.

Вторая команда спросит логин единственного администратора (например, `ikra_admin`), создаст длинный случайный пароль, запишет секреты в Cloudflare и покажет пароль **только в вашем терминале**. Сохраните его в менеджере паролей. Откройте `https://АДРЕС-САЙТА/admin` и войдите с этими данными. Электронная почта не обязательна. Регистрации и создания дополнительных администраторов в интерфейсе нет. Повторный запуск заменяет доступ этого же администратора. Восстановление доступа — повторный запуск `npm run admin:remote`: пароль заменится, старые сессии перестанут работать.

Каталог, акции, разделы, контакты и заказы теперь общие для всех устройств. На уже открытой странице изменения подхватываются при возвращении на вкладку или в течение 30 секунд.

Не загружайте только `dist` на обычный статический хостинг: этой версии нужен также Worker API. `npm run deploy` размещает обе части вместе.

## 4. Подключить Telegram

1. Откройте официального [@BotFather](https://t.me/BotFather), выполните `/newbot` и создайте бота. Сохраните выданный токен.
2. Откройте чат с созданным ботом и нажмите **Start** или напишите `/start`. Если заказы нужны в группе, добавьте бота в группу и отправьте ему команду `/start@ИМЯ_БОТА`.
3. В Cloudflare откройте свой Worker → **Settings → Variables and Secrets**. Добавьте секрет `TELEGRAM_BOT_TOKEN` с токеном бота. Не добавляйте его в `VITE_*`, исходники или чат.
4. Узнайте `chat_id` своего чата через метод Telegram `getUpdates`. Его можно посмотреть локально по инструкции ниже. Для группы идентификатор обычно отрицательный — сохраните знак минус.
5. Добавьте второй секрет `TELEGRAM_CHAT_ID` и примените изменения.

Чтобы получить `chat_id` без вставки токена в адресную строку и историю браузера, выполните:

```bash
node scripts/telegram-chat.mjs
```

Скрипт прочитает токен скрытым вводом в терминале, вызовет официальный Telegram API и покажет только идентификаторы чатов. Если список пуст, сначала отправьте боту `/start`, затем повторите. Скрипт не отправляет сообщений.

Во вкладке **Огляд** статус Telegram означает наличие настроек, но не проверяет действительность токена. Оформите пробный заказ с сайта. Он должен появиться в **Замовлення** и в вашем Telegram. При ошибке её причина отображается возле заказа; кнопка **Повторити** дожидается результата отправки.

Если Telegram сообщает о недействительном токене (`401 Unauthorized`), получите актуальный токен у BotFather и замените `TELEGRAM_BOT_TOKEN` в Cloudflare → Worker → **Settings → Variables and Secrets**, затем примените изменения. Локальный `.dev.vars` не обновляет секреты опубликованного сайта; для локальной проверки замените токен также в `.dev.vars` и перезапустите Worker. После замены нажмите **Повторити** у сохранённого заказа. При ошибке «чат не найден» проверьте `TELEGRAM_CHAT_ID` и отправьте боту `/start`; при запрете доступа разблокируйте бота или восстановите его права в группе.

Уведомление оформлено по образцу: имя, телефон, город, отделение/адрес Новой почты, товары с весом и количеством, сумма, комментарий, источник перехода, IP и время по Киеву. Адрес Новой почты — отдельное необязательное поле формы. Источник берётся из `utm_source`, иначе из домена внешнего перехода, иначе `direct`; `utm_medium` и `utm_campaign` тоже сохраняются. Первое посещение запоминается на время вкладки, поэтому переход по внутренним разделам не затирает источник.

IP берётся Worker из заголовков Cloudflare `CF-Connecting-IP` / `CF-Connecting-IPv6`, не из полей формы. Локально обычно будет `127.0.0.1`; на опубликованном сайте — адрес, который видит Cloudflare. Если IP недоступен, сообщение покажет «не визначено». Эти сведения доступны в защищённой админке. Форма содержит пояснение о сохранении IP/источника и передаче заказа менеджеру в Telegram.

Заказ сначала записывается в D1, затем отправляется сообщение. Если Telegram недоступен, заявка не теряется: отправка повторяется по расписанию каждые 5 минут с увеличивающейся задержкой, до 10 попыток. Статус виден в админке; кнопка **Повторити** запускает новую попытку. После подключения бота начнут отправляться и ранее накопившиеся уведомления. При редком сбое после принятия сообщения Telegram, но до записи результата, возможно повторное уведомление; сам заказ при сетевом повторе не дублируется.

## 5. Подключить загрузку фотографий

Создайте аккаунт [Cloudinary Free](https://cloudinary.com/users/register_free). В его настройках API Keys возьмите Cloud name, API Key и API Secret.

Для настройки через терминал IntelliJ выполните:

```bash
npm run photos:setup -- --remote
```

Введите три значения по подсказкам (ввод скрыт). Команда сохранит настройки локально и отправит их в Cloudflare. Для настройки только локального сайта используйте `npm run photos:setup`, затем перезапустите локальный сервер Cloudflare. Ключи не нужно отправлять в чат. После настройки откройте редактор товара, выберите JPG, PNG или WebP до 5 МБ с телефона или компьютера и сохраните товар. Фото автоматически загрузится в хранилище.

Либо добавьте настройки вручную:

В том же разделе секретов Worker добавьте:

- `CLOUDINARY_CLOUD_NAME`
- `CLOUDINARY_API_KEY`
- `CLOUDINARY_API_SECRET`

В админке во вкладке **Огляд** появится статус подключённой загрузки фото. Загрузка выполняется через защищённый Worker: секрет Cloudinary не передаётся посетителям. Поддерживаются JPG, PNG и WebP до 5 МБ.

Существующие изображения в `public/` работают и без Cloudinary. Пока он не подключён, можно использовать текущие фото и ссылки на изображения. Загрузка новых файлов в таком случае покажет понятное сообщение о необходимости настройки. Неиспользуемые загруженные фото автоматически не удаляются; их можно удалять в Cloudinary.

## 6. Позже подключить свой домен

Домен можно купить отдельно у Hostinger или другого регистратора. Пакет хостинга покупать не нужно.

1. Добавьте купленный домен в Cloudflare на Free-плане.
2. У регистратора замените nameservers на два адреса, которые покажет Cloudflare. Если у домена уже работает почта или другие сервисы, сначала перенесите их DNS-записи.
3. Дождитесь активного статуса домена в Cloudflare.
4. В настройках Worker откройте **Domains & Routes → Add → Custom Domain** и добавьте свой домен. Cloudflare создаст DNS-запись и HTTPS-сертификат.

Для тестирования достаточно `workers.dev`; для магазина с реальными покупателями Cloudflare рекомендует собственный домен. Менять D1 и повторно переносить каталог при подключении домена не нужно.

## Локальная проверка без облачного аккаунта

Нужен Node.js 22.18+; в текущей среде используется Node.js 24.

```bash
npm install
npm run db:local
npm run admin:local
npm run dev:cloudflare
```

Откройте `http://127.0.0.1:8787` и `/admin`. Данные сохраняются в локальной D1 в `.wrangler/`, пароль — в `.dev.vars`; оба пути исключены из Git. Для локальных Telegram/Cloudinary можно добавить секреты из `.dev.vars.example` в `.dev.vars`. Без них локальный заказ всё равно сохраняется, отправки и загрузки отключены.

`npm run dev` остаётся деморежимом витрины с данными браузера. Обхода входа в `/admin` нет даже в разработке; для админки используйте `npm run dev:cloudflare`. `npm run preview` показывает уже собранный сайт с локальным Worker; сначала нужны локальные миграции и пароль.

Проверки:

```bash
npm test
npm run build
```

Интеграционные тесты используют локальный эмулятор D1 и подменяют Telegram/Cloudinary. Они не отправляют реальные сообщения и не загружают файлы во внешний аккаунт.

## Стоимость и резервная копия

Используем бесплатные Workers и D1, Cloudinary Free. У бесплатных планов есть лимиты; при их превышении запросы могут ограничиваться. Переходить на платный тариф для первого запуска не требуется. Лимиты и использование видны в панелях Cloudflare и Cloudinary.

Перед крупными правками сделайте выгрузку D1:

```bash
npx wrangler d1 export DB --remote --output backup.sql
```

Файл содержит заказы и контакты покупателей: храните его локально и не добавляйте в Git.

Официальные справки: [Worker + файлы сайта](https://developers.cloudflare.com/workers/static-assets/), [workers.dev](https://developers.cloudflare.com/workers/configuration/routing/workers-dev/), [свой домен](https://developers.cloudflare.com/workers/configuration/routing/custom-domains/), [секреты](https://developers.cloudflare.com/workers/configuration/secrets/), [D1](https://developers.cloudflare.com/d1/platform/pricing/), [Cloudinary Free](https://cloudinary.com/pricing).
