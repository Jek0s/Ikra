# IKRA DeLuxe: подготовка реальной админки

## Почему нужна база

`npm run build` создаёт статические файлы React. Они не умеют хранить общие товары, изображения и заказы. Локальное редактирование через localStorage служит только для проверки интерфейса в IntelliJ IDEA. Для настоящего сайта подключаем Supabase: это готовые база PostgreSQL, API, загрузка изображений и система входа по email/паролю. Собственный сервер и SQL-операции для редактирования каждого товара писать не нужно.

## Что делаем один раз — ещё до покупки домена

1. Зарегистрируйтесь на https://supabase.com и создайте новый проект. Сохраните пароль от базы в безопасном месте. Дождитесь готовности проекта.
2. В Supabase откройте **SQL Editor → New query**, вставьте содержимое `supabase/schema.sql`, нажмите **Run**. Это создаст таблицы `products`, `orders`, `admin_users`, политики RLS, загрузку фотографий и функцию оформления заказа.
3. В разделе **Authentication → Users** создайте пользователя с email владельца и собственным сильным паролем (способ создания зависит от текущего интерфейса Supabase). Скопируйте его **User UID**. Самостоятельная регистрация покупателей для админки не нужна.
4. В **SQL Editor** выполните SQL, заменив UUID на настоящий идентификатор пользователя:

```sql
insert into public.admin_users (user_id)
values ('ВАШ-USER-UID');
```

5. В настройках Supabase найдите **Project URL** и **publishable key** (или прежний `anon` ключ). Не используйте `service_role` / `secret` ключ во фронтенде.
6. Рядом с `package.json` создайте `.env.local`:

```dotenv
VITE_SUPABASE_URL=https://ВАШ-ПРОЕКТ.supabase.co
VITE_SUPABASE_ANON_KEY=ВАШ-PUBLISHABLE-KEY
```

7. Перезапустите Vite (`Ctrl+C`, затем `npm run dev`). Зайдите на `http://localhost:5173/admin`, введите email и пароль. Теперь товары, фотографии и заказы хранятся в Supabase, а не только в вашем браузере.
8. В админке нажмите **Товари → Додати товар**, заполните название, подпись, цену, вес, категорию, описание и загрузите JPG/PNG/WebP до 5 МБ. Включите **Опубліковано** и нажмите **Зберегти товар**. На главной странице товар появится после загрузки каталога.

**Важное замечание:** после подключения облачной базы локально отредактированные данные из браузера автоматически НЕ переносятся. Добавьте товары через админку или отдельно импортируйте их в Supabase. Настоящие исходные фотографии сохранены в `public/products`, и их можно выбрать при заполнении товаров.

### Если SQL уже выполнялся в предыдущей версии

Чтобы категория `Щуча / інша` могла сохраняться в уже созданной таблице, выполните отдельно:

```sql
alter table public.products drop constraint if exists products_category_check;
alter table public.products add constraint products_category_check
  check (category in ('red', 'black', 'sets', 'other'));
```

## Запуск на хостинге

1. Настройте `.env.local` до сборки на своём компьютере, чтобы публичный Project URL и publishable key попали в React-клиент. Эти данные специально публичны; безопасность обеспечивается правилами Supabase RLS. Никогда не вставляйте секретный ключ.
2. Выполните `npm install`, затем `npm run build`.
3. Загрузите **содержимое** папки `dist` на Hostinger. Для прямого перехода на `/admin` настройте возврат `index.html` для SPA (в проекте есть `public/.htaccess` для Apache).
4. Сайт будет открыт на вашем домене, а вход в админку останется по адресу `https://ВАШ-ДОМЕН/admin`.
5. Важные предпусковые проверки: реальные контакты и условия доставки/возврата, политика конфиденциальности и согласие на обработку контактов, настройка антиспама для оформления заказа, тест на мобильном и desktop, резервные копии базы.

## Ограничения текущего магазина

- Без Supabase локальный режим применяется **только при разработке** (`npm run dev`). На опубликованном сайте админка без базы не предоставляет доступ к редактированию.
- Уведомления о заказах в Telegram пока не подключены.
- Акционные наборы в интерфейсе — витрина предложений, а не полноценные записи заказа. Для реальных заказов наборов потребуется добавить их как товары в базу с корректными ценами/составом и связать кнопки с корзиной.
- Проверку рабочей сборки необходимо выполнить на компьютере с установленными npm-зависимостями. В среде подготовки архива реестр npm не отвечал.
